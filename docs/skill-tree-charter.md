## 序言

技能树不是一份"写完就完"的目录，而是一个**需要持续代谢的活体**。

技术在变，岗位要求在变，面试问法也在变。任何静态的知识清单，从落笔那一刻就开始过期。因此本项目对技能树的目标**不是"完整"**——完整既不可达（叶子无穷），追求它还会让维护成本压垮团队——而是三条可持续的性质：

> **可导航（Navigable）· 可保鲜（Fresh）· 可修剪（Prunable）**

本宪章的存在，是为了让"不断完善、不断健全技能树"这件事有**规则可依**，而不依赖某一次的热情或某一个人的记忆。哪怕是很小的技能，也是技能树的一部分——但它必须按规则挂枝、按规则保鲜、按规则退役。

## 第一条 · 使命与边界

### 1.1 使命

以技术提升能力，以能力提升面试竞争力，从而适应时代与需求。技术推动需求、需求反推技术，故技能树必须持续生长。

### 1.2 本树是什么

本树是一棵**求职 / 面试能力树**（Job-Readiness & Interview Competency Tree）。它的组织方式、深度取舍、内容配比，全部服务于"**能通过技术面试，并具备对应真实能力**"这一目标。

判断任何内容该不该进树，第一性问题恒为：
> **它是否影响学习者的技术能力或面试表现？**

### 1.3 本树刻意不是什么

为避免误导学习者产生"学完即完整工程师"的错觉，本树**刻意不覆盖**以下能力域：

| 不覆盖域 | 说明 |
|---|---|
| 产品感与需求分析 | 属产品能力树，非本树范围 |
| 业务建模与领域知识 | 高度行业相关，无法通用化 |
| 协作沟通与向上管理 | 属职场软技能树 |
| 技术领导力与团队管理 | 属管理能力树 |
| 职业规划与薪酬谈判 | 属求职策略，非技术能力 |

### 1.4 边界须在产品内可见

上述边界**不得只写在文档里**。技能树页面（`/skills`）必须向用户明示本树的定位与不覆盖清单。**声明缺失视为违宪**。

## 第二条 · 分层定义（trunk / branch / leaf）

### 2.1 三层定义

| 层 | 名称 | 定义 | 典型 | 半衰期 |
|---|---|---|---|---|
| `trunk` | 主干 | 稳定核心原理，跨技术栈可迁移 | 操作系统、网络协议、算法、并发模型、设计原则 | > 10 年 |
| `branch` | 分支 | 技术域 / 框架 / 生态，成规模但会被替代 | React、Vue、Spring、Kubernetes、Redis | 3–10 年 |
| `leaf` | 叶子 | 具体工具 / 版本 / 配置 / 技巧 | React 19 的 `use` hook、K8s 某 API 版本、某 CLI 参数 | < 3 年 |

### 2.2 判定标准（三问定层）

对任一知识节点依次追问：

1. **迁移性**：换一套技术栈后还成立吗？ → 成立倾向 `trunk`。
2. **被依赖度**：有多少其他节点以它为前置？ → 被广泛依赖倾向 `trunk`。
3. **版本敏感度**：内容里出现具体版本号 / 产品名 / API 签名了吗？ → 出现越多越倾向 `leaf`。

三问结论冲突时，**就低不就高**（宁可判为 branch/leaf，以获得更严的保鲜要求）。

### 2.3 章与节的层级归属

- **章（chapter）只分 `trunk` 或 `branch`**，是技能树上肉眼可见的"枝"。
- **`leaf` 不单独成章**，而是承载在 section 的内容里（具体工具、版本、技巧、命令）。
- 因此：**新出的框架/库/工具，默认先作为 leaf 写进最近的 branch 章**，只有当它形成独立生态且被广泛面试考察时，才提案升为独立 branch 章（见第三条 3.5）。

## 第三条 · 准入（新增什么才配进树）

### 3.1 五问准入测试

拟新增任一节点，必须五问全过，任一不过即驳回：

1. **面试相关**：过去 12 个月内，它在真实技术面试中被问到过吗（或明显将被问到）？
2. **能力相关**：掌握它是否切实提升工程能力，而非仅为记忆性谈资？
3. **可锚定**：能否指向官方文档 / RFC / 论文 / 官方源码作为事实来源？
4. **非重复**：现有 317 节中是否已有等价内容？若有，应**增强旧节而非新增**。
5. **可挂枝**：能否明确挂到某个既有 trunk/branch 之下？若挂不上，说明缺的是枝干而非叶子（走 3.5 提案流程）。

### 3.2 最小完备件（Definition of Done）

任何新节点合入时必须同时具备，缺一不可：

- ✅ **V1 六段式完整**：心智模型 / 核心知识点（锚定官方）/ 为什么重要 / 常见坑 / 动手自测 / 面试视角
- ✅ **事实锚定官方**，不臆造
- ✅ **时效元数据块**（第四条 4.1）
- ✅ **至少 1 条 `doc:` 互链**（前置 / 对比 / 后续三选一），杜绝孤岛
- ✅ **命名符合规范**（第八条 8.5）

### 3.3 挂枝规则

- 就近挂到**语义最相关**的 trunk/branch 章，而非"最空的章"。
- 一个 leaf 只有一个"家"（主挂点），其他相关性通过 `doc:` 互链表达，**禁止内容复制**。
- 跨方向相关（如 Node.js ↔ 后端 API 设计）一律用互链，不重复写。

### 3.4 粒度

- **下限**：一个节点应能支撑一次 3–5 分钟的面试问答。碎到"一个 CLI flag"的知识，应并入相邻节点的「常见坑」或「进阶」，不单独成节。
- **上限**：一个节点若需超过 15 分钟才能讲完，应拆分。

### 3.5 升格提案（leaf → branch 章）

某个 leaf 满足**全部**下列条件时，方可提案升为独立 branch 章：

1. 已在多个方向/岗位 JD 中作为独立技能项出现；
2. 自身已形成子生态（有多个需要分节讲解的子主题，≥ 5 节）；
3. 连续 2 个季度复审中均被标记为"高热度"。

升格须同步更新第 2.4 分层表与审计脚本的 `LAYER_MAP`。

## 第四条 · 时效与保鲜

### 4.1 时效元数据块（机器可解析）

每个 section 的 `content` **最顶部**（六段式之前）写单行引用块，作为该知识点的"保鲜标签"——读者一进来即可看到它何时被核验、锚定哪个版本：

```
> 时效 | 核验=2026-08-02 | 风险=中 | 版本=React 19 | 来源=官方
```

字段规则：

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `核验` | 是 | `YYYY-MM-DD` | 最近一次人工核对事实的日期 |
| `风险` | 是 | `低` / `中` / `高` | 过期风险，决定复核 SLA |
| `版本` | 否 | 自由文本 | 内容所锚定的版本，如 `React 19`、`K8s 1.31`；纯原理类填 `无` 或省略 |
| `来源` | 是 | `官方` / `RFC` / `论文` / `标准` | 事实锚定类型 |

> 该块严格遵守**零 schema 漂移**：只写在 markdown 内，不新增 seed 字段、不改注入器、app 无需改动。

### 4.2 风险分级与复核 SLA

| 风险 | 复核周期 | 适用 | 超期后果 |
|---|---|---|---|
| `高` | **90 天** | 框架大版本、云厂商 API、工具链、AI/LLM 生态 | 审计告警，进入下次复审队列首位 |
| `中` | **180 天** | 生态实践、性能建议、配置范式 | 审计告警 |
| `低` | **365 天** | 协议、算法、OS 原理、设计原则 | 审计提示 |

### 4.3 默认风险推定

未显式标注风险时，按层级推定：`trunk → 低`、`branch → 中`、含具体版本号的 leaf 内容 → `高`。**推定不免除标注义务**，审计仍将其计为"缺时效标签"。

### 4.4 超期处理

超期节点不自动删除，按序处理：**重新核验官方源 → 更新事实 → 更新 `核验` 日期**。若核验发现该技术已死，转第五条修剪流程。

## 第五条 · 修剪与退役

### 5.1 枯枝判定（四条件）

同时满足 **≥3 条**即判定为枯枝：

1. 官方已宣布停止维护 / EOL；
2. 主流 JD 中连续 12 个月未出现；
3. 已有明确的事实继任者（且继任者已在树内）；
4. 面试中仅作为"历史对比"被提及，不再作为独立考点。

### 5.2 三级退役路径（不直接删除）

```
   活跃 (active)
      │  枯枝判定通过
      ▼
   维护 (maintenance) ── 停止扩充，仅修错；标注「已进入维护期」
      │  连续 2 个季度无面试热度
      ▼
   归档 (archived)  ──── 降级为相邻节点内的「演进脉络 / 历史对比」一段
      │  完全无历史教学价值
      ▼
   删除 (removed)   ──── 需在路线图更新记录中留痕
```

### 5.3 不轻易删的理由

面试仍会问"为什么不用 jQuery 了""AngularJS 的脏检查有什么问题"。**技术之死本身就是高价值考点**。因此枯枝优先降级为"演进脉络"素材，而非物理删除——这也正是 V2 规范里「演进脉络」块的用途。

## 第六条 · 复审节奏（双轨制）

### 6.1 触发式复审（事件驱动）

监听到下列事件后 **2 周内**完成相关节点复审：

| 触发源 | 关注对象 |
|---|---|
| 框架大版本发布 | React / Vue / Angular / Node.js / TypeScript / Spring |
| 基础设施发版 | Kubernetes / Docker / Nginx / 主流云厂商 |
| 标准与提案 | ECMAScript 年度版本、重要 RFC、W3C/WHATWG 变更 |
| 行业大会 | React Conf、VueConf、KubeCon、QCon、Google I/O |
| 重大安全事件 | CVE 高危、供应链攻击（触发安全类章节复审） |
| AI/LLM 生态 | 主流模型能力代际变化、Agent/RAG 工程范式变化 |

### 6.2 周期式复审（日历驱动）

| 周期 | 动作 |
|---|---|
| **每月** | 跑 `npm run audit:tree`，处理红线项与超期高风险节点 |
| **每季度** | 分层复审一个方向（前端 / 后端 / 运维 轮转）；执行枯枝判定；更新热度标记 |
| **每年** | 复审第 2.4 分层表本身（是否有 branch 该升 trunk、trunk 该拆分）；复审第 1.3 边界清单 |

### 6.3 复审的最小产出

每次复审必须在 `docs/skill-tree-roadmap.md` 的"更新记录"追加一条，含：复审范围、变更节点数、新增/降级/归档清单。**无留痕的复审视为未发生**。

## 第七条 · 健康度仪表与红线

### 7.1 八项指标

由 `node scripts/skilltree_audit.mjs`（`npm run audit:tree`）产出：

| # | 指标 | 含义 | 目标 |
|---|---|---|---|
| 1 | 规模 | 模块 / 章 / 节数量 | 持续增长 |
| 2 | 分层分布 | trunk : branch 章数比 | trunk 不低于 40% |
| 3 | V1 达标率 | 六段式完整的 section 占比 | **100%** |
| 4 | V2 深度覆盖 | 含「进阶」「专家」的占比 | 滚动提升 |
| 5 | 互链健康 | `doc:` 链接有效性 + 孤岛节点数 | 失效 0；孤岛持续下降 |
| 6 | 时效覆盖率 | 含时效块的 section 占比 | 滚动至 100% |
| 7 | 超期节点 | 按风险 SLA 判定已过期的节点 | 高风险超期为 0 |
| 8 | 命名规范 | 章标题前缀一致性 | 100% 一致 |

### 7.2 红线（审计失败 / 退出码 1）

触碰任一即视为违宪，必须修复：

- ❌ **V1 六段式达标率 < 100%**（内容地基退化）
- ❌ **存在失效 `doc:` 互链**（导航断裂）
- ❌ **trunk 章占比 < 40%**（树被叶子淹没，失去骨架）

其余指标以告警（warning）呈现，不阻断，但须进入复审队列。

### 7.2.1 互链相关性红线（质量审）

互链不等于"有链接即可"，必须**主题相关**。`doc:` 链接分三类，仅跨模块类受红线约束：

| 类型 | 判定 | 处置 |
|---|---|---|
| 同章兄弟（同 `chapter`） | 天然相关 | 放行 |
| 同模块跨章（同 `module`） | 域内相邻 | 软规则，仅抽样人工抽检 |
| **跨模块**（不同 `module`） | **必须落在「授权桥接集」** | 否则视为红线违规，待复核 |

授权桥接集（机器副本见 `scripts/charter_links.mjs`）：
1. `scripts/charter_island.mjs` 的 `BRIDGES` 跨模块章对（课程路径对齐）；
2. `scripts/charter_ai_bridge.mjs` 的 AI 反向桥接宿主章（`ai-c1` ↔ 16 个宿主章）；
3. V2 增强阶段经人工逐条审定、带具体备注的「合法跨引用」（见脚本 `VETTED_XMOD_RAW`，如 `fe-c16↔be-api`「HTTP 语义规范用法」、`be-nosql↔op-c4`「ES 也是日志检索底座」）。

审计器 `scripts/charter_links.mjs`（`npm run audit:links`）扫描全部 `doc:` 链接，报告分类与跨模块违规清单；CI 中以 `node scripts/charter_links.mjs --strict` 运行，红线违规即退出码 1，阻断合入。

> **基线（2026-08-02）**：1218 条链接，跨模块 270 全部合规，0 违规、0 失效。新增跨模块链接若未在授权集中，CI 必拦截——沿用即等于把"机械补未审"的欠账制度化地消灭。

### 7.3 执行

```bash
npm run audit:tree              # 健康度仪表（宪章第七条），红线不过则退出码 1
npm run audit:tree -- --verbose # 打印超期 / 孤岛 / 缺标签完整明细
npm run audit:v2                # V1/V2 结构校验
npm run charter:fix -- --dry    # 合宪化预演（不写盘）
npm run charter:fix -- --all    # 执行合宪化：章名归一 + 时效打标
```

### 7.4 工具链（宪章的可执行实现）

| 文件 | 职责 | 纪律 |
|---|---|---|
| `scripts/skilltree.config.mjs` | **宪章的机器可读副本**：分层表、SLA、风险推定、命名规则、红线阈值 | 改此文件必须同步改宪章正文，反之亦然 |
| `scripts/skilltree_audit.mjs` | 八项指标 + 三条红线裁决 | **只读**，绝不写盘 |
| `scripts/charter_fix.mjs` | 批量落实机械性要求（章名、时效块） | **幂等**，已合规者跳过，可安全重跑 |
| `scripts/charter_island.mjs` | 孤岛治理：为无出链节补 `doc:` 互链（同章兄弟 + 上游前置 + 跨模块桥接） | **幂等**，只处理无出链节，重跑=0 变更；零 schema 漂移 |
