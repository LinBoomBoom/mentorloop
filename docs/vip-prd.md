# MentorLoop 支付 VIP 功能 · 产品规格文档（PRD）

> 文档状态：Draft v1 · 作者：产品通 · 日期：2026-08-01
> 适用产品：MentorLoop（前端 / 后端 / 运维三方向的"学面一体"导师平台）
> 范围：VIP 会员的**价值主张、付费链路、吸引力评估、定价策略（含 9.9/月 方案）**

---

## 0. TL;DR（给老板的一句话结论）

1. **VIP 现在"卖不动"不是价格问题，是"货还没备齐"问题。** 代码里支付未接入、付费内容池为空（3 套试卷全部免费）、页面吹的 4 个卖点（AI 深度模拟面试 / 学习路径定制 / 1v1 简历诊断 / 内推资源库）**目前一个都没实现**。先补价值，再谈定价。
2. **¥9.9/月 ≠ 一定更好。** 单价降 66%，需要转化率翻 ~2.93 倍才能和 ¥29 打平收入。对"学习订阅"这类理性消费，价格弹性通常只有 1.5–2.5 倍，盲降大概率**收入反而更低**。
3. **正确动作**：把 ¥29 当对照，用 A/B 实测 ¥19.9 / ¥9.9 的「转化 × 留存 × 客单价」综合 LTV，按 LTV 而非注册数决策；同时重建 VIP 真实权益与支付链路。

## 一、背景与问题（Why）

### 1.1 现状盘点（基于代码实测，非猜测）

| 维度 | 现状 | 证据 |
|---|---|---|
| 套餐配置 | 月度 ¥29、年度 ¥199，但 `enabled: false`（**未上线**） | `server/api/vip/plans.get.ts` |
| VIP 身份判定 | `user.vip.level > 0`；DB 存 `users.vip` = JSON `{level, expireAt}` | `app/stores/auth.ts` getter / `server/utils/db.ts` |
| 内容门禁 | `exam_sets.vip_only` 字段 + 交卷接口 `requireVip` 校验（非 VIP 返回 403） | `server/api/exam/submit.post.ts:8`、`db.ts:163` |
| 付费内容池 | 种子数据 3 套试卷**全部 `vipOnly: false`** → 当前**零付费内容** | `data/seed-content.json` |
| "AI 深度模拟面试" | 仅有 `/api/interview/ask` 问答接口，**无对话式模拟面试** | 全仓检索无 mock/simulate 实现 |
| "学习路径定制" | 未实现（学习路径为固定三方向） | 全仓检索无 path/customize 实现 |
| "1v1 简历诊断" | 未实现 | 全仓检索无 diagnose/resume 实现 |
| "内推资源库" | 未实现 | 全仓检索无 referral 实现 |
| 支付能力 | **无任何支付服务商、无订单/订阅表、无 webhook** | 全仓无 stripe/alipay/wechat/order 关键词 |
| 上线前留存手段 | VIP 页仅一个"留邮箱通知我"表单（本地标记，不落库） | `app/pages/vip/index.vue` |

### 1.2 核心问题

- **价值缺口**：对外宣传的 VIP 权益大部分是占位文案，用户付了钱拿不到对应交付物，会引发退款/投诉/口碑反噬。
- **链路缺口**：即使有人想买，也没有下单 → 支付 → 开通 → 续费/到期 → 退款 的完整闭环。
- **定价问题（用户提问）**：当前 ¥29/月 是否合适？改 ¥9.9/月 是否更好？—— 这个问题**只有在价值与链路补齐后才有意义**，但我们可以先用模型给出决策框架。

## 二、目标与成功指标

### 2.1 产品目标

1. 让 VIP 成为"用户主动想买"，而非"被弹窗骚扰"。
2. 付费转化率健康，且**不牺牲免费用户的增长漏斗**（MentorLoop 的免费内容本身就是获客引擎）。
3. 付费用户留存（续费率）正向，LTV > 3× 获客成本。

### 2.2 指标体系（北极星 + 驱动 + 健康）

> ⚠️ 基线值目前**均无埋点数据**，下表基线为"需上线后 2–4 周观测得到"，目标值为行业经验区间，**须经 A/B 验证**。

| 类型 | 指标 | 基线（待测） | 目标值 |
|---|---|---|---|
| 北极星 | 月度付费净收入（MRR） | ￥0（未上线） | 上线 90 天 ≥ ￥X（按 GA 流量估算后填） |
| 驱动 | VIP 页 → 下单转化率 | — | ¥29 档 ≥ 1.5%；¥9.9 档 ≥ 4% |
| 驱动 | 付费用户 30 日留存率 | — | ≥ 60% |
| 驱动 | 年度套餐占付费比 | — | ≥ 25%（锁现金+降流失） |
| 健康 | 免费用户次留/7 留 | — | 不下降（VIP 门禁不得伤害免费漏斗） |
| 健康 | 退款率 | — | < 5% |
| 健康 | 付费内容使用率（买了真用） | — | ≥ 70%（防"买了不用"虚假繁荣） |

## 三、用户故事

- 作为**求职者（应届/转行）**，我希望用一杯奶茶的钱解锁更贴近真实面试的专属试卷和 AI 陪练，以便提高上岸概率。
- 作为**免费用户**，我希望能先免登录浏览全部基础内容，在被明确告知"这是 VIP 专属"后才被引导付费，以便我自主决定是否升级。
- 作为**付费用户**，我希望开通后权益**立即、稳定**生效，且能随时查看到期时间、自助续费/取消，以便获得可预期的服务。
- 作为**运营/财务**，我希望每笔订单可核对、可退款、可对账，以便合规与核算。
- 作为**产品经理**，我希望能分群 A/B 测试价格与权益组合，以便用数据而非拍脑袋定策略。

## 四、功能范围

### 4.1 In Scope（本期必须交付）

1. **真实付费权益（先补货）**
   - 至少 **3 套 VIP 专属模拟试卷**（标记 `vip_only=1`，含选择+笔试，交卷后正常出判分与复盘）。
   - **AI 模拟面试 MVP**：基于现有 `/api/interview/ask` 扩展为"多轮追问 + 评分 + 薄弱点报告"（不要求真人视频，文本/语音转写即可）。
   - **学习路径定制 MVP**：根据用户答卷薄弱点，自动生成"下一步该学哪几节"的推荐路径。
2. **支付与订阅闭环**
   - 订单表 `orders`、订阅表 `subscriptions`（含 `plan_id / status / period / expire_at / provider / transaction_id`）。
   - 接入至少一家支付服务商（微信支付 / 支付宝；学生群体优先微信）。
   - 支付成功 webhook → 写 `subscriptions` → 更新 `users.vip{level, expireAt}` → 前端 `isVip` 实时生效。
   - 到期自动降级（`expireAt < now` 时 `level=0`），续费/复购路径。
   - 退款与原路退回，状态对账。
3. **购买与展示体验**
   - VIP 页 `enabled=true`，套餐/权益/价格可配置（接 `plans.get`）。
   - 付费墙：VIP 专属试卷预览可见、交卷时引导开通（复用现有 403 逻辑）。
   - 个人中心：显示 VIP 状态、到期日、管理订阅入口。

### 4.2 Non-goals（本期不做，防止范围蔓延）

- **不做** 1v1 真人简历诊断、真人内推（高人力成本、难规模化，留到"高阶套餐"另议，见 §八）。
- **不做** 企业/团队批量采购（B 端账号体系本期不建）。
- **不做** 多币种 / 海外支付。
- **不做** 永久买断制（只做订阅，保证持续收入与持续交付压力）。
- **不**为提升转化而把基础免费内容改为付费（保护获客漏斗）。

## 七、VIP 是否吸引用户？（吸引力分析）

### 7.1 用"价值-价格"框架看

| 要素 | 当前情况 | 吸引力判断 |
|---|---|---|
| 免费层价值 | 极高：三方向学习路径、面试题库、模拟试卷**全部免登录可览** | 免费层是强获客钩子，但也**抬高了付费门槛** |
| 付费层差异点 | 理论上有 4 个卖点，但 **0 个已上线**，且 0 套付费试卷 | **差异点目前为 0，用户无付费理由** |
| 付费心理账户 | 求职/学习投入，用户愿为"能帮我上岸"付费 | 需求真实，但要求"看得见的交付" |
| 信任 | 新平台、无支付、无评价 | 转化天然偏低，需社会证明 |

### 7.2 竞品锚定（求职/学习/AI 面试类）

| 产品 | 定价 | 备注 |
|---|---|---|
| 力扣 LeetCode Premium | ~$35/年（≈¥35/月等效） | 题库解锁为主 |
| 牛客 | 题库免费；简历修改 ¥99–299/次 | 付费在"服务"非"会员" |
| 极客时间 | 单课 ¥68–199，年卡 ~¥365 | 内容版权付费 |
| AI 面试/求职助手（新兴） | ¥30–99/月 | 直接竞品 |
| 知识星球/社群 | ¥199–599/年 | 圈子溢价 |

**结论**：¥29/月 对标"AI 面试类工具"属合理中位；¥9.9/月 属"预算/冲动档"，价格敏感学生友好，但易被解读为"东西不值钱"。

### 7.3 吸引力总判断

> **以当前状态，VIP 几乎不可能吸引用户**——不是定价问题，而是：
> 1. 付费内容池为空（没东西可买）；
> 2. 头部卖点全部未交付（买了拿不到）；
> 3. 免费层已足够好，削弱付费动机。
>
> **先把 §四.1 的"真实权益 + 支付闭环"补齐，吸引力问题才会从"能不能卖"变成"卖多少钱"。**

## 八、定价分析：¥9.9/月 是否比 ¥29/月 更好？

### 8.1 收入打平模型（关键算术）

设每月触达付费墙的可转化用户数为 **N**，月费 **P**，转化率 **c**：

```
月度收入 R = N × c × P
```

要让 ¥9.9 与 ¥29 **收入持平**：

```
c(9.9) = c(29) × (29 / 9.9) = c(29) × 2.93
```

**即：单价砍到 1/3，转化率必须翻 ~2.93 倍，收入才不降。**

### 8.2 举例（N=1,000 触达用户/月，仅示意）

| 方案 | 单价 | 假设转化率 | 付费人数 | 月度收入 |
|---|---|---|---|---|
| A：¥29 | 29 | 2.0% | 20 | **¥580** |
| B：¥9.9 | 9.9 | 4.0%（翻 2×） | 40 | ¥396（**−32%**） |
| C：¥9.9 | 9.9 | 6.0%（翻 3×） | 60 | ¥594（打平略超） |

> 现实里，学习类订阅降价 66%，转化率通常只涨 **1.5–2.5 倍**（理性消费、非冲动品）。**所以盲降到 9.9，大概率收入更低，只是"注册数好看"。**

### 8.3 ¥9.9 的"非收入"利弊

| 利 | 弊 |
|---|---|
| 低价降低决策摩擦，扩大漏斗顶部 | 客单价塌缩，LTV 承压 |
| 对学生/应届（MentorLoop 核心人群）友好 | 容易被解读为"低质"，损害品牌 |
| 可作"引流价"培养习惯，再向上 sell 年包 | 与年包 ¥199 冲突：12×9.9=¥118.8，年包仅"贵 ¥80"，靠 1v1+内推 撑，而这两样本期不做 → 年包失真 |
| 降低"买贵了"的退款/差评风险 | 若日后想涨价，老用户锚定难迁移 |

### 8.4 年包定价联动（重要）

若月包降到 ¥9.9，原年包 ¥199（≈¥16.6/月）会显得**既不便宜也不值**。建议联动：
- 月包 ¥9.9 时，年包重定价 **¥99–129**（≈¥8.25–10.75/月），用"年付立省 2 个月"话术，保住现金与留存。
- 年包的"1v1 简历诊断 / 内推"**必须限次/轻量化**（如每年 1 次 AI 简历报告 + 内推岗位清单），否则以 ¥99–199 的人力成本必然亏损。

### 8.5 决策建议（不拍脑袋，用实验）

1. **别直接二选一**。把 ¥29 作对照，上线 A/B：`¥29`（对照）/ `¥19.9` / `¥9.9` 三档，按**实验分组**切流。
2. **看 LTV 不是看注册数**：`LTV ≈ ARPPU × 毛利率 × 1/月流失率`。¥9.9 若靠高转化+低流失跑赢 LTV，才"更好"。
3. **分人群**：对学生认证/应届人群可给 ¥9.9 教育价，对在职转行人群用 ¥29 标准价——同产品双轨，兼顾量与利。
4. **价值先到位**：在 §四.1 权益补齐前，任何价格都救不了转化率。

> **一句话答用户**：¥9.9/月 不是"更好"，是"更激进的获客杠杆"。它能否更好，**取决于转化率能否翻 3 倍 + 年包重定价 + 权益真实交付**。先用 A/B 测，再定。

## 九、风险与合规

- **支付合规**：接入微信/支付宝需营业执照与类目资质；虚拟商品（会员）需明确"不支持随意退款"的条款告知。
- **个人信息保护（个保法/GDPR）**：订阅/邮箱/支付信息加密存储；退款、注销时按要求删除；跨境不考虑。
- **虚假宣传风险**：在 4 个卖点全部交付前，**VIP 页文案必须与实际权益一致**，否则构成虚假宣传。
- **续费明示**：自动续费须在开通前显著告知，提供便捷取消入口（监管硬要求）。
- **数据可信度**：本文所有基线/目标均为**待观测假设**，不代表已测数据；上线后以埋点为准。
