# 项目自评 · 缺漏 / 瑕疵 / 可改进清单（2026-08-02）

> 评审方法：不凭记忆，实跑 `npm run audit:tree --verbose`、抽看 `data/seed-content.json` 真实内容、grep `server/` 与 `app/` 的支付/测试痕迹、核查项目根测试与 CI 配置。
> 结论一句话：**宪章"结构指标"全绿，但产品闭环、工程保障、内容深度三处有明显欠账。**

---

## 一、严重缺漏（影响"能不能赚钱 / 稳不稳"）

### 1. 支付闭环是空壳 ⚠️ 最该补
- **实测**：`server/api/` 下无任何 `payment / order / subscribe / webhook / stripe / wechatpay` 端点；`app/` 仅有 `vip/index.vue` 引导页与 `useLearning` 的 `isVip` 判定（门禁展示用），**没有下单、没有支付回调、没有"付完款→写 `users.vip`"的逻辑**。
- 现状：4 套 VIP 考卷 + `requireVip` 门禁（返回 403）+ `/vip` 引导页都做了，但用户**付不了钱，付了也不会被标记 VIP**。
- 后果：VIP 变现链路根本跑不通，付费层是"展示用空壳"。
- 若修：接一个支付服务商（微信支付/Stripe）→ 建 `orders`/`subscriptions` 表 → 加 `payment` 回调端点 → 在回调里写 `users.vip{level,expireAt}`。

### 2. VIP 实际权益稀薄
- 产品卖点（AI 深度模拟面试 / 学习路径定制 / 1v1 简历诊断 / 内推资源库）此前已标注"均未实现"，仅有 `/api/interview/ask` 基础问答。
- 后果：即便支付通了，付费用户买到的"差异化价值"有限，转化与续费存疑。

## 二、工程瑕疵（影响"改了会不会炸"）

### 3. 零自动化测试 / 零 CI
- **实测**：项目根无 `test/ tests/ __tests__/ e2e/`，无 `.github/` CI，package.json 无 `vitest/jest/playwright/cypress` 声明。
- 现状：所有"重灌无损""E2E 通过"都是对话里手动验证，无回归保护。每次改 seed 或脚本都可能悄悄破坏，靠人肉审计兜底。
- 若修：引入 vitest（单元，验脚本幂等/解析器）+ playwright（E2E，验 /skills 点亮、/exam 门禁、/interview 作答）；加 GitHub Actions 在 push 时跑 `audit:tree` + 测试。

### 4. 运营脚本"建好但没真转过"
- `review_queue.mjs` / `leaf_register.mjs` / `trigger_watchlist.mjs` 生成了待办与脚手架，但**从没基于它们做过一次真实复审或登记动作**。
- 宪章"季度复审"靠手动跑脚本 + 人看，**没有定时触发**（无 automation/cron）。时效 SLA 现在"0 超期"只是因为内容刚写；90 天后高风险节点会过期，但没人会被自动提醒。
- 若修：建一个定时任务（每季/每月）自动跑 `review_queue` 并产出待办清单，推送提醒。

## 三、内容深度不均（形式主义达标）

### 5. V2 深度项几乎空白
- **实测**（`audit:tree --verbose`）：「演进脉络」仅 **1/330 节（0.3%）**、ASCII 图示仅 **6/330 节（1.8%）**。
- 现状：V1 六段式 100% 是达标，但宪章鼓励的"演进脉络（技术怎么演变来的）""图示化（怎么画出来）"基本没写。内容偏"知识点罗列"。
- 若修：挑选高风险/主干章（ai-c1、be-dist、op-c8），每章补 1 节"演进脉络"+ 关键处加 ASCII 图示。

### 6. 知识图谱"有量无质审"
- **实测**：`doc:` 互链 1218 条、孤岛 0、失效 0（漂亮）。
- 但链接是 `charter_island.mjs` 按规则**机械补**的（同章兄弟 + 上游前置 + 跨模块桥接），**没审过"这条链接对读者是否有导航价值"**，可能互链了弱相关节点。
- #45–#49 只覆盖了"数量/失效"，**没覆盖"链接质量"复审**。
- 若修：抽样人工审 20~30 条互链，建立"相关性评分"或至少在宪章加一条互链质量红线。

### 7. 老章节未做逐题技术复核
- **实测**：新章（ai-c1 / op-c8 / op-c5-s10）质量高、锚定官方（CNCF/OWASP/Backstage/DORA）；老章 fe-c9 React 抽样也扎实（JSX 心智模型清晰）。整体内容**不是骨架**，质量合格。
- 但 330 节里大量老章节的"事实锚定"是否都还准？尤其 **ai-c1 标"风险=高·来源=OpenAI/Anthropic"**，在 2026-08 多模型格局下具体 API/模型名/SLA 数字可能已过时——时效块挂着，但**还没真跑过一次复审**。
- 若修：以 `review_queue` 输出的高风险清单为依据，对 ai-c1、op-c8 做一次真实技术复核。

## 六、建议修补优先级

1. **【P0】支付闭环**（#1 缺漏）—— 否则 VIP 模式不成立。
2. **【P0】测试 + CI**（#3）—— 否则所有"无损/合宪"承诺无回归保障。
3. **【P1】运营脚本真正运转**（#4）—— 建定时复审，让时效 SLA 从"挂着"变"响着"。
4. **【P1】VIP 权益实质化**（#2）—— 让付费有真实差异价值。
5. **【P2】内容深度补强**（#5/#6/#7）—— 演进脉络、互链质量审、高风险章复审。
6. **【P2】搜索 / 移动端 / 学习路径**（#8/#10/#11）。
