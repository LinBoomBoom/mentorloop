## 一、缘起与共识（2026-08-02）

- **平台使命**：以技术提高能力、以能力提高面试竞争力，从而适应时代与需求。技术推动需求、需求反推技术，故技能树必须**持续完善、不断健全**——哪怕是很小的技能，也是技能树的一部分。
- **已落地基座**：41 章 / 317 知识点，V1 六段式 100% 达标，V2 第一波（进阶/专家/知识图谱/图示）已落地。
- **关键共识（与 AI 的反思对齐）**：现有内容可作"**求职/面试能力树**"的**主干**，但须满足三个修正条件才算合格主干（见下）。

## 二、三修正条件 → 运作哲学

| # | 反驳点 | 修正条件 | 落到模型 |
|---|---|---|---|
| 反驳1 | 缺的不仅是叶子，是整根 limb（如 AI/LLM 工程） | 先补 trunk 级枝干 | **R1 封口主干** |
| 反驳2 | "组合成完整树"暗示叶子只增不减，但知识会死 | 目标从"完整"改为"可导航+可保鲜+可修剪" | **R2 保鲜与修剪** |
| 反驳3 | 这棵"主干"是被框定的（偏面试/求职） | 明确它是职业树的一个子树，非 universal | **R3 定位澄清** |

**trunk / branch / leaf 模型**
- `trunk 主干` = 稳定核心原理（OS、网络、算法、协议）——相对稳定，但也会生长。
- `branch 分支` = 技术域 / 框架（React、K8s、Spring…）。
- `leaf 叶子` = 具体工具 / 版本 / 技巧 / 新库——快变、会枯。
- **目标不是"完整"（不可达且致瘫），而是：可导航（定位任意叶子）+ 可保鲜（标时效/版本）+ 可修剪（废弃降级）。**

## 三、五条可持续工作流（R1–R5）

### R1 · 封口主干（反驳1：缺 limb）
- **R1-a** 新增 **AI/LLM 工程 trunk 章**（建议 `ai-llm` 跨域）：LLM 应用架构 / RAG / Agent 编排 / 评测 evals / 提示与上下文工程 / AI 编码工程化 / 框架生态 / 安全合规 / 成本延迟治理。锚定 OpenAI·Anthropic·Google 官方、RAG 论文、HELM/MT-Bench。
- **R1-b** 复审 **平台工程/IDP** 与 **DevSecOps** 是否已逼近 trunk 级，决定独立成章或并入运维。

### R2 · 保鲜与修剪（反驳2：叶子会死）
- **R2-a 规范**：定义时效元数据块（`> 时效: 核验=2026-08-02 | 风险=中 | 版本=v19 | 来源=官方`），扩展进 `v2-style-guide.md`。
- **R2-b 打标**：给现有 317 节滚动加时效标签，高频面试章优先。
- **R2-c 校验**：扩展 `scripts/v2_validate.mjs`，机械检测"缺时效 / 超期"，可定期运行。
- **R2-d 修剪**：季度复审 + 废弃降级 SOP（明确 jQuery/AngularJS 类枯枝的处理范式）。

### R3 · 定位澄清（反驳3：被框定的树干）
- 标注本树定位 = "求职/面试能力树"，并在导航页声明**刻意不覆盖**的能力（产品感、业务建模、协作沟通、技术领导力），避免误导"学完即完整工程师"。

### R4 · 叶子持续生长（用户：小技能也算）
- **R4-a 登记机制**：任何新框架/库/工具/技巧都作为 leaf 挂到最近 trunk/branch，含命名、最小粒度、锚定官方、互链规则。
- **R4-b 触发更新**：维护"大版本 / RFC / 大会"驱动的复审索引（React/Vue 大版本、K8s 发版、React Conf/QLConf…），让更新被动跟随时代。
- **R4-c 面试题扩充**：58 → 数百（按方向滚动，每章配 5–10 道）。
- **R4-d VIP 内容池**：填充考卷/付费内容，使 VIP 门禁有真实权益。

### R5 · 运营化
- 本路线图文档（只追加不覆盖）。
- 上述校验/复审可定时运行的命令（如 `node scripts/v2_validate.mjs`、`npm run audit:freshness`）。

## 四、执行纪律

1. **零 schema 漂移**：所有增强只在 `section.content` 的 markdown 内表达，不动 seed 字段、不改注入器、app 无需改。
2. **可审分批**：每章建完停等"继续"；大批量前先小样。
3. **事实锚定官方 + 标时效**：每条知识注明来源与核验日期，使"新鲜度"可审计。
4. **生长有章法**：新叶子走 R4-a 登记规则，不随意堆砌。
