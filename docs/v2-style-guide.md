# MentorLoop 知识树 V2 增强规范（v2-style-guide）

> 生效日期：2026-08-02 ｜ 适用范围：data/seed-content.json 全部 section 的 `content` 字段
> 原则：**零 schema 漂移（Zero Schema Drift）**——V2 全部增强只在 section 的 `content` markdown 内表达，不新增 seed 字段、不改注入器契约、app 无需改动即可渲染。

## 一、为什么有 V2

V1 解决了"有没有、对不对"（六段式学习层：心智模型 / 核心知识点（锚定官方）/ 为什么重要 / 常见坑 / 动手自测 / 面试视角），事实已锚定官方信源。

V2 在 V1 之上补三件事，把"知识点"升级为"知识网络"：

1. **分级深度**：同一知识点给「入门 / 进阶 / 专家」三档纵深，初学者能入门、面试者能深挖。
2. **知识图谱互链**：跨章、跨方向指出"相关但不同"的知识点，形成可漫游的网络而非孤岛。
3. **版本边界与演进 + 关键图示**：说明"为什么这样演进"、用 ASCII 图呈现结构/流程，降低理解成本。

## 二·零、时效元数据块（宪章第 4.1 条 · 必填）

> 依据：`docs/skill-tree-charter.md` 第四条。本节是宪章在书写层的实现细则。

每个 section 的 `content` **最顶部**（六段式之前）必须有一行时效标签：

```
> 时效 | 核验=2026-08-02 | 风险=高 | 版本=React 19 | 来源=官方
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `核验` | 是 | `YYYY-MM-DD` | 最近一次人工核对事实的日期 |
| `风险` | 是 | `低` / `中` / `高` | 决定复核 SLA：**高 90 天 / 中 180 天 / 低 365 天** |
| `版本` | 否 | 自由文本 | 所锚定版本，如 `React 19`、`K8s 1.31`；纯原理类可省略 |
| `来源` | 是 | `官方` / `RFC` / `论文` / `标准` | 事实锚定类型 |

**风险怎么定**：trunk 章默认 `低`，branch 章默认 `中`；版本迭代快的章（React/Vue/Node/构建工具/Spring/NoSQL/K8s/IaC）强制 `高`。该规则固化在 `scripts/skilltree.config.mjs` 的 `HIGH_RISK_CHAPTERS` 与 `riskOf()`。

**批量补标**：`npm run charter:fix -- --fresh`（幂等，已有标签的节自动跳过）。

## 二、V2 标记语法（写在 `content` 内，位于六段式之后）

### 1) 分级深度（可选，按知识点价值添加）
```
### 进阶
（比「核心知识点」更深一层：边界条件、源码/协议级细节、易混淆对比，2–4 句）

### 专家
（专家级延伸：生产实战、性能拐点、权威出处 RFC/论文/官方源码指引，1–2 句）
```

### 2) 知识图谱互链（推荐每个 section 都有）
```
## 相关知识图谱
- 前置基础：[fe-c16-s1 事件循环](doc:frontend/fe-c16/fe-c16-s1) — 理解 X 前应先掌握 Y
- 横向对比：[be-nosql-s2 MongoDB](doc:backend/be-nosql/be-nosql-s2) — 与本节关系/取舍
- 后续进阶：[op-c7-s3 状态后端](doc:devops/op-c7/op-c7-s3) — 学完本节可往这走
```
链接语法：`[显示名](doc:<moduleId>/<chapterId>/<sectionId>)`。互链必须是**真实相关**（前置/对比/后续），禁止堆砌无关链接。

### 3) 演进脉络（仅「有演进故事」的知识点添加）
```
### 演进脉络
（为何从 A 演进到 B：如 REST→gRPC、虚拟化→容器→K8s、SQL→NoSQL，1–3 句点明驱动力）
```

### 4) 关键图示（架构/流程类知识点添加）
用 fenced code block 承载 ASCII 图，语言标记用 `text`/`plain` 以便渲染识别：
````
### 结构图示
```text
   Client ──req──> API Gateway ──> Service A
                              └──> Service B (gRPC)
```
````

## 三、质量纪律

- **不破坏 V1**：六段式六段必须完整保留，V2 块一律追加在后。校验脚本 `scripts/v2_validate.mjs` 同时检查 V1 六段式与 V2 标记。
- **互链要真相关**：每一条 `doc:` 链接都要能回答"为什么放这条"——是前置、对比还是后续。
- **深度要递进**：「进阶」不重复「核心知识点」已说的；「专家」给可查证出处，不空谈。
- **图示服务理解**：图只为讲清结构/时序，不为装饰；复杂图用 ASCII，避免外部图片依赖。

## 四、落地节奏（增量、可审）

- 第一波（本规范随附）：8 个新增补章（fe-c16/17/18、be-test/api/nosql、op-c6/7）做完整 V2 示范，并反向给相关旧章加「相关知识图谱」桥接块，打通新旧知识网络。
- 后续滚动：按"高频面试章优先"逐章补 V2，每章一 PR、可审。
- 长期目标：全部 41 章 / 317 section 均带「相关知识图谱」互链，核心架构章带图示与演进脉络。

## 五、校验

`node scripts/v2_validate.mjs` 输出：V1 六段式达标率、含 `### 进阶`/`### 专家` 的 section 数、含 `doc:` 互链的 section 数、含 ASCII 图的 section 数，以及示例互链是否指向真实存在的 sectionId。
