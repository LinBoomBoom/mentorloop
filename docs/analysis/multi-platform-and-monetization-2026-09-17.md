## 0. 先修正上一轮结论

上一轮我说「技术栈不需要改」，前提是"只有 Web + 桌面两端、且桌面端是离线单机"。**这个前提被你推翻了，所以结论要改：多端确实撑不住。**

但**要改的范围比你想的小**。先澄清一个容易误判的点：

### 好消息：Nuxt 的 server 层天然就是 API 服务，不用重写

`server/api/` 下那 56 个端点，本来就是标准 HTTP 接口。小程序的 `wx.request`、APP 的 fetch 可以直接调 `https://你的域名/api/modules` —— **不需要另起一个后端框架，不需要重写业务逻辑。**

真正撑不住的是下面这几项，而且**每一项都有明确的改造点，没有一项需要推倒重来**：

| 项 | 现状 | 多端下的问题 | 必须改？ |
|---|---|---|---|
| **数据库** | SQLite 单文件 | 多端并发写、无法水平扩容、无法多实例部署 | **必须** → PostgreSQL |
| **桌面端离线单机库** | `userData/mentorloop-data` 独立库 | 与云端多端**根本冲突**：用户在小程序学的，桌面端看不到 | **必须**决策 |
| **鉴权** | HttpOnly Cookie（兼容旧 `x-token` 头） | 小程序不用 Cookie；APP 需要长期 token | **必须** → Bearer 双模 |
| **限流** | 进程内 Map（23 处） | 多实例部署时计数按实例数放大 | 必须（多实例前）→ Redis |
| **媒体存储** | 本地磁盘 | 多端无法共享访问 | 必须 → 对象存储 |
| **API 版本化** | 无 | 多端版本不一致，改接口会打破旧客户端 | 建议 |
| **业务框架** | Nuxt 4 + Nitro | **完全够用，保留** | 不用改 |
| **前端** | Vue 3 + antd + Tailwind | 小程序/APP 另写，Web 端逻辑保留 | 不用改 |

### 一个关键的战略冲突，你必须先决定

**「桌面端离线单机」和「多端数据同步」是互斥的。**

现在桌面端是 2026-08-18 拍板的「离线单机、账号本机注册、不做 Web↔桌面互通」。一旦小程序和 APP 上线，用户会理所当然地认为「我在手机上刷的题，电脑上应该能看到」。

三条路，只能选一条：

| 方案 | 做法 | 代价 | 适合 |
|---|---|---|---|
| **A. 桌面端转在线**（推荐） | 桌面端也登录云端账号，本地只做缓存；断网时可用缓存，联网后同步 | 放弃"完全离线可用"，需要同步逻辑 | 多端协同是主线时 |
| B. 保留离线，明确告知 | 桌面端仍是独立产品，与云端账号无关，启动时明示"本端数据独立" | 用户困惑、口碑风险 | 桌面端定位为"单机软件"时 |
| C. 双模式 | 可离线匿名用，登录后才同步 | 同步冲突处理复杂 | 最理想，但工作量最大 |

**我的建议：A。** 理由是你要做多端且要赚钱，数据孤岛会直接伤害留存和付费转化。

## 1. 架构改造：分层演进，不要一次性重写

### 1.1 演进节奏（按用户量触发，不要提前过度设计）

```
现在（0–1k 用户）        多端开发启动时           多端上线后（1w+）
Web + 桌面                + 小程序 + APP          按需扩容
    ↓                          ↓                      ↓
SQLite 够用          →   迁 PostgreSQL        →   读写分离 / 缓存
内存限流够用         →   引入 Redis           →   多实例 + 负载均衡
Cookie 够用          →   Bearer 双模鉴权      →   完整 API 版本化
磁盘存媒体           →   对象存储             →   CDN
```

**关键原则：在真正需要的前一步做，而不是现在全做。**

### 1.2 现在就该做的三件低成本预埋（不做将来会痛）

这三件事成本都很低，但**越晚做代价越高**：

**(1) 数据访问层抽象 —— 最重要的一件**

`server/utils/db.ts` 已经 1845 行，正好借拆分的机会加一层：

```
server/
  db/
    schema.ts        # 表结构
    migrations/      # 每个版本一个文件
    queries/         # 按业务域：user.ts / exam.ts / interview.ts / content.ts
    client.ts        # 连接与方言适配
```

**核心约束：业务代码不许出现 SQLite 专有语法。**

现在要重点排查的方言痕迹（这些迁 Postgres 时会炸）：
- `INTEGER PRIMARY KEY AUTOINCREMENT` → `SERIAL`
- `datetime('now')` / `strftime()` → 用 JS 传时间戳
- `INSERT OR IGNORE` / `INSERT OR REPLACE` → `ON CONFLICT`
- `PRAGMA` 语句
- 布尔用 0/1 还是 true/false
- 表名/列名的大小写与引号习惯

建议：现在就写一条测试，把所有 SQL 语句抓出来做方言扫描。**这比将来手工翻 1845 行便宜得多。**

**(2) 鉴权双模**

现状 `getUser(event)` 已经兼容 `x-token` 头，改造面很小：

```
登录成功 → 返回 { token, expiresAt }
Web：     token 写入 HttpOnly Cookie（保留现状）
小程序/APP：token 存本地 storage，请求带 Authorization: Bearer <token>
```

需要补的：
- 长有效期 refresh token（APP 不适合 7 天就过期重登）
- 设备/端标识（用于"我的设备"管理）
- 小程序走微信 openid 一键登录的入口

**(3) API 版本化约定**

现在就给新增接口加 `/api/v1/` 前缀，老接口保持不动，逐步迁移。**不要等 APP 上线后才加，那时候旧客户端已经在跑了。**

### 1.3 小程序端有几个前置条件（非技术，但会卡住上线）

| 条件 | 说明 |
|---|---|
| **域名必须备案 + HTTPS** | 小程序强制要求，个人主体也能备案，但需要时间 |
| **主体资质** | 如果涉及付费，个人主体小程序**不能做虚拟支付**（iOS 端尤其严格），需要企业主体 |
| **内容审核** | 教育类目可能需要资质 |

> ⚠️ 这条要提前规划：**个人主体的小程序在 iOS 上无法售卖虚拟商品**。既然明确要盈利，建议直接注册企业/个体户主体。这个流程要几周，越早启动越好。

### 1.4 技术栈最终结论

| 层 | 结论 |
|---|---|
| Web 前端 | **保留** Nuxt 4 + Vue 3（SSR 是 SEO 资产，别丢） |
| 服务端 | **保留** Nitro，逐步把 `server/` 拆成可独立部署的 API |
| 数据库 | **现在不用改，多端开发启动时迁 PostgreSQL** |
| 缓存/限流 | 多实例前引入 Redis |
| 桌面端 | 保留 Electron，但**改在线账号 + 本地缓存** |
| 小程序 | uni-app 或 Taro（复用 Vue 技术栈，成本低） |
| APP | 同上，一套代码多端；或先只做小程序验证需求 |

> **uni-app / Taro 建议**：你团队是 Vue 栈，用 uni-app 可以一套代码同时出小程序 + APP + H5，学习成本最低。不建议上 Flutter（要学 Dart）、也不建议 React Native（要学 React）。

## 2. 产品定位：深度思考

### 2.1 先看清这个赛道最致命的问题

IT 面试准备这个赛道有一个结构性缺陷，不解决它，做多少功能都难赚钱：

> **用户生命周期极短 —— 找到工作就走。**

具体表现：
- 平均使用周期 1–3 个月，不是几年
- 一次性消费，即使满意，明年也不一定再来（除非跳槽）
- 付费窗口只在求职期那几周
- 免费替代品质量极高（JavaGuide 这类开源仓库 10w+ star）

**算一笔账（这是判断盈利可能性的核心）：**

```
会员 ¥29/月 × 平均订阅 2 个月 = LTV ≈ ¥58
获客：SEO 内容摊薄后，单个注册用户成本约 ¥2–5
付费转化率按 2% 算 → 单个付费用户 CAC ≈ ¥100–250

CAC(100~250) > LTV(58)  →  纯会员制结构性亏损
```

**结论：纯 C 端会员订阅在这个赛道是数学上不成立的模式。**

要赚钱，只有三条路：**提高 LTV、提高客单价、降低 CAC（批量）**。

### 2.2 三种定位对比

| 定位 | LTV | CAC | 竞争 | 我的评价 |
|---|---|---|---|---|
| **A. 通用面试题库 + 会员** | 低（¥58） | 高 | 极激烈 | ❌ 数学上不成立 |
| **B. 垂直方向深耕**（AI 工程 / 运维） | 中（可复用、口碑传播） | 中 | 较小 | ✅ 值得做 |
| **C. B 端机构 + C 端高客单价服务** | **高** | **低（批量）** | 少 | ✅✅ **最可能赚钱** |

### 2.3 我建议的定位（三层结构）

> **不做"面试题库"，做"技术能力评估与提升平台" —— 免费内容获客，C 端服务变现，B 端机构规模化。**

这个定位的三个支撑：

**① 定位升级：从"面试准备"到"能力评估"**

"面试准备"是 1–3 个月的事；"能力评估"是在职者也需要的（我到底什么水平？该补什么？）。**生命周期从 3 个月延长到 3 年。**

你的资产恰好支撑这个定位：408 个技能点的路线图、16,453 道题、章节内容、考试系统、掌握度追踪 `user_skill_mastery`。

**② C 端：免费引流 + 高客单价服务（不是会员）**

| 层 | 内容 | 定价 |
|---|---|---|
| 免费 | 全部课程章节、大部分题库、基础考试 | ¥0（SEO 获客） |
| 轻量付费 | AI 面试次数包、专属模考卷、简历解析 | ¥29–99（降低决策门槛） |
| **利润层** | 简历优化（人工）、真人模拟面试、1v1 求职陪跑 | **¥299–2000+** |

**关键洞察：¥29/月 的会员赚不到钱，但 ¥299 的简历优化一单就顶 5 个月会员。** 而且后者是"结果导向"，用户付费意愿高得多。

**③ B 端：机构授权（我认为这是最现实的现金流）**

你已经有的资产，对机构是现成的解决方案：

| 客户 | 需求 | 你现成的东西 |
|---|---|---|
| **高校计算机院系** | 教学辅助、阶段测验、就业指导 | 4 方向课程体系、57 套卷、考试系统、进度管理 |
| **IT 培训机构** | 学员练习、结业考核、就业率背书 | 全套内容 + 后台管理 |
| **企业 HR / 技术团队** | 候选人初筛、内部技术评估 | 题库 + 考试 + 评分报告 |

**为什么 B 端更适合你现在的处境：**
- 一个 500 人的院系 × ¥30–50/人/年 = ¥15,000–25,000/年
- 签 10 所 = ¥15–25 万/年，**比找 500–800 个 C 端会员容易得多**
- 你缺的功能不多：多租户（机构/班级）、批量授权、机构端数据看板
- 回款稳定、续费率高（机构换系统成本高）

### 2.4 方向选择：主推 AI 工程 + 运维

你的 411 章分布：前端 152 / 后端 117 / 运维 78 / AI 工程 64。

- **前端、后端是红海**，JavaGuide 这类免费资料最密集，你打不出差异化
- **运维（78 章）** 竞争小得多，且运维的"故障排查/场景题"是八股文覆盖薄弱的地方
- **AI 工程（64 章、2,777 题）** 是**增量市场** —— 岗位新、人才缺、付费意愿强、资料少

**建议：AI 工程 + 运维作为主推方向（决定付费转化），前端/后端保留作为 SEO 流量入口（决定获客成本）。**

不是删掉前后端内容，而是**营销资源分配上不均衡**：首页、投放、文案主推 AI 工程和运维。

## 3. PC / 桌面端差异化（不做数字人语音之后）

### 3.1 核心原则

> **PC 端不是"移动端的放大版"，而是"承担深度任务的那一端"。**

移动端（小程序/APP）天然适合：等车时刷 10 道题、看一个知识点、收到每日打卡提醒。
PC / 桌面端应该承接：需要长时间、大屏幕、文件处理、复杂交互的**重度任务**。

这样分工后，四端不是互相抢用户时长，而是**各司其职、同一账号串联**。

### 3.2 五个差异化场景（按推荐优先级）

#### ① 技能图谱大屏 —— 用户会专门打开电脑看的那个功能 ⭐⭐⭐

你有 408 个技能点的路线图（`roadmap.vue` 585 行），手机上展示 408 个节点基本不可读。

**做成"我的技能地图"**：
- 整屏展示 4 个方向 × 技能点的掌握度热力分布
- 点击任意技能点 → 下钻到该题、该章节、我的正确率、上次练习时间
- 标注"目标岗位要求 vs 我当前水平"的差距
- 一键生成"补缺计划"（你现在有 `study_plans` 表但只有 4 条记录）

**为什么值得做**：这是唯一一个"用户会为了看它而打开电脑"的功能，也是天然的留存锚点和付费钩子（完整图谱/差距分析可设为付费）。

#### ② 完整限时模考 + 深度复盘报告 ⭐⭐⭐

2 小时的完整模拟考试，只有 PC 端合适。移动端适合刷单题。

**复盘报告在 PC 上做深**：
- 多维能力雷达（不是现在首页那种装饰图，是真实数据）
- 与历史成绩的趋势对比（你有 `exam_records`，但缺对比视图）
- 逐题解析 + 知识点定位
- 薄弱点自动回流到课程章节（表现在回流没接通）

**为什么值得做**：考试是"确定性最强"的功能（服务端计时、防重复提交都做了），也是最能体现"专业性"的场景。

#### ③ 简历驱动的完整工作流 ⭐⭐⭐（我认为这是最好的差异化）

这是 PC 端独有的重工作流，而且**天然把"简历"和"面试"两个求职环节串起来**——目前没有哪家做通了：

```
上传简历（PDF/Word）
  → AI 解析出技术栈与项目经历        [你已有 mammoth + pdf-parse + resume.ts]
  → 基于他的真实技术栈生成"专属面试清单"（不是通用八股，是针对他简历会问的）
  → 逐项练习，标记掌握程度
  → 输出"面试准备度报告"：哪些项目说不清、哪些技术没准备
  → 简历修改建议（回到第一步）
```

**为什么是最好的差异化**：
- 文件处理天然属于 PC 端（移动端上传 PDF 体验差）
- 直接关联求职结果，**付费意愿远高于刷题库**
- 天然是付费点（简历诊断 ¥99–299）
- 技术底座你已经有了大半

#### ④ 导出与打印 ⭐⭐

错题本、知识卡片、复习计划 → 导出 PDF。考研/考公会打印资料，求职也一样。成本低，作为会员权益很合适。

#### ⑤ 离线可用（仅 Electron 桌面端）⭐⭐

如果选了方案 A（桌面端转在线），可以保留"本地缓存 + 断网可用"，联网后同步。这在飞机上、网络差的环境下是真实价值。

### 3.3 优先级建议

| 优先级 | 项目 | 工作量 |
|---|---|---|
| P0 | ③ 简历驱动工作流（这是差异化核心 + 付费点） | 中 |
| P0 | ② 模考复盘报告做深（现成数据，主要是前端呈现） | 小 |
| P1 | ① 技能图谱大屏（408 节点，需要交互设计） | 中 |
| P2 | ④ 导出 PDF | 小 |
| P2 | ⑤ 离线缓存 | 中 |

## 4. 盈利点拓展

### 4.1 三层盈利模型

```
第一层  免费内容（全部课程 + 大部分题库 + 基础考试）
        目的：SEO 获客、建立信任、不设付费墙
                    ↓ 转化 2–5%
第二层  轻量付费（¥29–99）
        AI 面试次数包 · 专属模考卷 · 简历解析 · 完整技能图谱
        目的：筛选出有付费意愿的用户，降低决策门槛
                    ↓ 转化 10–20%
第三层  高客单价（¥299–2000+）   ★ 利润主要来源
        简历优化（人工）· 真人模拟面试 · 1v1 求职陪跑 · 内推
                    +
        B 端机构授权（¥30–50/人/年）  ★ 稳定现金流
```

| AI 模拟面试次数包 | ¥39/10 次 | 低（需配额控制） | ⭐⭐⭐ |
| VIP 专属模考卷 | 含在会员 | 低 | ⭐⭐ 已有 8 套 VIP 卷 |

| **真人模拟面试** | **¥299–599/场** | 高（人力） | ⭐⭐ 需要面试官资源 |

### 4.3 B 端盈利点（建议重点开拓）

| 客户 | 产品形态 | 定价参考 |

| 高校计算机院系 | 机构账号 + 班级管理 + 阶段测验 | ¥30–80/人/年 |

## 5. 需要你拍板的 4 个决策

1. **桌面端数据策略**：转在线（放弃纯离线）/ 保持离线单机 / 双模式？
   → 我的建议：**转在线**，否则多端同步无解，会伤害留存和付费转化。

2. **主推方向**：继续四方向平均用力，还是主推 AI 工程 + 运维（前后端做 SEO 引流）？
   → 我的建议：**主推 AI 工程 + 运维**。

3. **盈利主路径**：C 端会员 / C 端高客单价服务 / **B 端机构授权**？
   → 我的建议：**B 端机构 + C 端高客单价服务双轮，会员只做入口**。C 端会员单独跑是数学上亏的。

4. **小程序主体**：现在是否启动企业/个体户主体注册？
   → 我的建议：**立刻启动**。个人主体小程序在 iOS 上无法售卖虚拟商品，这个流程要几周，会卡住商业化节奏。

## 6. 接下来 30 天的建议（按新前提重排）

| 优先级 | 事项 | 为什么 |
|---|---|---|
| 1 | **启动企业主体注册 + 域名备案** | 非技术，但周期最长，会卡死小程序商业化 |
