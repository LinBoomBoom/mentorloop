# 季度复审与废弃降级 SOP

> 操作化宪章 **第五条（修剪与退役）** 与 **第六条（复审节奏）**，把"原则"变成"可执行的四步法 + 三级退役路径 + 留痕模板"。
> 配套工具：`review_queue.mjs`（生成复审队列）、`v2_validate.mjs`（合规校验）、`npm run audit:tree`（健康度仪表）。
> 纪律红线：**零 schema 漂移**——所有保鲜动作只在 markdown 内容内改 `> 时效` 块的「核验」日期与事实，不新增 seed 字段、不改注入器、app 无需改动。

## 1. 双轨复审节奏（宪章 6.1 / 6.2）

| 轨道 | 触发 | 动作 | 截止 |
|---|---|---|---|
| **触发式**（事件驱动） | 框架大版本 / 基建发版 / 标准提案 / 行业大会 / 重大安全事件 / AI 生态代际变化 | 复审相关节点（见 `trigger-review-checklist.md` 映射表） | 事件后 **2 周内** |
| **周期式**（日历驱动） | 每月 / 每季度 / 每年 | 每月跑审计；每季度分层复审一个方向 + 枯枝判定；每年复审分层表本身 | 见下表 |

| 周期 | 动作 |
|---|---|
| **每月** | 跑 `npm run audit:tree`，处理红线项与超期高风险节点 |
| **每季度** | 分层复审一个方向（前端 / 后端 / 运维 轮转）；执行枯枝判定；更新热度标记 |
| **每年** | 复审第 2.4 分层表（branch 是否该升 trunk、trunk 是否该拆分）；复审第 1.3 边界清单 |

## 2. 季度复审四步法

### Step 1 · 健康度快照
```bash
npm run audit:tree      # 红线：V1 100% / 失效链 0 / trunk ≥ 40%
node v2_validate.mjs    # 时效覆盖率 / 风险分布 / 格式错误 / 超期节点
```
记录三项指标，作为本季基线。

### Step 2 · 拉复审队列
```bash
node review_queue.mjs   # 输出超期 + 临期(30天)节点，按紧急度排序
```
- **超期节点**：立即进入复审，优先于一切新增内容。
- **临期节点**：排进本季复审计划，按风险（高→中→低）+ 剩余天数排序。

### Step 3 · 方向分层复审
本季轮到的方向（前端/后端/运维轮转），逐章核对：
- 高风险章（config `HIGH_RISK_CHAPTERS`）逐节核验官方源是否变更；
- 标记「高热度」候选（连续 2 季度被面试/招聘高频提及，参见宪章 3.2）——为未来升层积累证据。

### Step 4 · 枯枝判定与降级
对本季轮到方向的全部节点跑「枯枝四条件」（§4），命中 ≥3 条即进入退役路径（§3）。

## 3. 废弃降级三级路径（宪章 5.2，不直接删除）

```
活跃 (active)
  │ 枯枝判定通过（§4 命中 ≥3）
  ▼
维护 (maintenance) ── 停止扩充，仅修错；标注「已进入维护期」
  │ 连续 2 个季度无面试热度
  ▼
归档 (archived)  ──── 降级为相邻节点内的「演进脉络 / 历史对比」一段（V2 规范「演进脉络」块）
  │ 完全无历史教学价值
  ▼
删除 (removed)   ──── 须在路线图更新记录留痕
```

**各级操作清单**
- **→ 维护**：在 section 顶部时效块加 `状态=维护期`；停止新增子节；仅接受纠错 PR。
- **→ 归档**：把"为什么重要 / 面试视角"改写为「演进脉络」口吻（技术之死本身是考点，如"为什么不用 jQuery"）；时效块标 `风险=低 来源=历史`。
- **→ 删除**：仅在确认零教学价值后；删除前在 `docs/skill-tree-roadmap.md` 更新记录写清"删除节点 + 理由 + 替代节点"。

> **不轻易删的理由**：面试常问"AngularJS 脏检查有什么问题""为什么不用 Redux 了"——技术之死是高价值考点，优先降级而非物理删除。

## 4. 枯枝判定四条件（宪章 5.1）

同时满足 **≥3 条**即判定为枯枝：
1. 官方已宣布停止维护 / EOL；
2. 主流 JD 中连续 12 个月未出现；
3. 已有明确的事实继任者（且继任者已在树内）；
4. 面试中仅作为"历史对比"被提及，不再作为独立考点。

## 5. 留痕模板（宪章 6.3：无留痕的复审视为未发生）

每次复审在 `docs/skill-tree-roadmap.md` 的「更新记录」追加一条，格式：

```
- **YYYY-MM-DD** **[季度复审 / 触发式复审]**（范围：前端/后端/运维/全树）
  - 健康度：V1 100% / 失效链 0 / trunk 57.1% / 时效覆盖 100% / 超期 N
  - 复审节点数：X（其中超期 Y、临期 Z）
  - 新增：—（或清单）
  - 降级：op-cX-sY「…」→ 维护期（命中枯枝 1/2/3）
  - 归档：… → 演进脉络段
  - 删除：…（理由 + 替代）
```
